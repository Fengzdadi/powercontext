# 产品简报：考前雷达 ExamRadar

> 产品负责人写给开发者（Qoder）的需求输入。需求拆解、技术设计、编码和调试由 Qoder 完成。

## 1. 要解决的问题

大学生期末复习时有三个反复出现的痛点：

1. **资料散**：课堂笔记（Markdown）、老师的课件（PDF）、往年试卷（PDF）、拓展阅读的论文（中英文 PDF）分散在各处，想找"上次笔记里讲两阶段锁的那段"要翻半天。
2. **不知道自己漏了什么**：老师公布了考试范围，但没人告诉你哪几章自己的笔记根本没记、哪些只记了一两句，而往年真题恰恰常考这些。
3. **复习没有记性**：刷题工具不知道你上次错在哪，每次都从头来；错题本靠手抄，复习间隔全凭感觉。

## 2. 目标用户与使用场景

- 一名正在准备期末考试的大学生，在自己电脑上本地运行，处理的是**自己的**课程资料。
- 典型一次使用（20–40 分钟）：打开 → 看到"上次你在 X 上错了两次，先复习这个" → 粘贴考试范围看雷达图 → 针对盲区做几道题 → 答错的题被记住 → 下次接着来。

## 3. 核心功能（必须全部实现）

### F1 资料导入，检索带出处
- 导入 Markdown（`.md`）、纯文本和 PDF（`.pdf`），每份资料标注类型：笔记 notes / 课件 slides / 往年试卷 exam / 论文 paper。
- 切块入库到 **seekdb**，每个块保留：来源文件名、页码（PDF）、所属标题路径（Markdown 的 `#` 标题；PDF 尽量识别页标题）。
- 同一张表上建 **VECTOR + HNSW** 向量索引和 **FULLTEXT（IK 分词，中英文都要能搜）** 全文索引。
- "问笔记"：输入一个问题，用 **`DBMS_HYBRID_SEARCH`（RRF 融合）** 检索，返回的每一段都标明 `文件 · 第几页 · 哪个标题`。配置了大模型时再生成一段带 [1][2] 引用的回答；没配置时直接展示带出处的原文段落。

### F2 考试范围覆盖雷达
- 学生粘贴老师给的考试范围（一行一个知识点，或带编号的列表）。
- 对每个知识点在 seekdb 里做混合检索，分别统计：
  - **笔记覆盖度**：在 notes / slides / paper 中能找到多少、多强的证据 → 判定 **已覆盖 covered / 薄弱 thin / 缺失 missing**；
  - **考试权重**：在往年试卷 exam 中被考到的强度（命中的题目数，能解析出分值更好）。
- 展示：雷达图（各知识点覆盖度，叠加考试权重）+ **盲区清单**（考试权重高但覆盖低的排最前），每个判定都能点开看到支撑它的证据段落和出处。
- 判定阈值要可配置，并用示例数据校准，结果要让人信服（README 里说明判定规则）。

### F3 复习教练（越用越懂你）
- **出题**：只从学生**自己的资料**里出题，优先针对薄弱/缺失/到期复习的知识点；每道题标明出自哪份资料哪一页。
  - 配置了大模型（OpenAI 兼容接口）时：基于检索到的原文生成选择题/填空题/简答题，并结合该知识点的历史错题（从 PowerContext 召回）针对性出题。
  - 没配置大模型时：规则出题（例如从笔记原句里挖空关键术语），功能依然完整可用。
- **判分**：给出对错、参考答案和原文出处；有大模型时可判简答题并指出误区。
- **记忆写入 PowerContext**（学习者的长期记忆）：
  - 每个知识点一张**掌握度卡片**（Leitner 间隔复习：盒号、答对/答错次数、下次复习日期），每次判分后**替换内容**生成新 revision，历次 revision 就是掌握度变化轨迹；
  - 每次答错写一条**错题记忆**（题目、学生答案、正确答案、出处）；
  - 一条**复习计划**记忆（打上 `bootstrap-context` 标签），每次判分/会话结束后更新；
  - 会话结束写一条**会话小结**。
- **新会话从记忆开始**：开始学习时调用 PowerContext `context/bootstrap`，首页直接显示类似"上次你在『事务隔离级别』上错了两次，先复习这个"；进入某个知识点时用 `context/prepare` 召回该知识点的历史错题。
- 有一个"我的记忆"页面，能看到 PowerContext 里关于自己的掌握度卡片（含 revision 历史）、错题和复习计划。

### F4 使用记录
- 真实记录每一次使用：学习会话（开始/结束/时长）、检索次数、覆盖分析、出题/答题、导入等，存进 seekdb。
- "使用记录"页面展示统计（会话数、累计时长、检索/答题次数、正确率变化），并能导出 CSV/JSON，作为"使用效果"数据的可核对来源。
- 自动化验证脚本产生的记录要能和真实使用区分开（例如单独的来源标记），统计时可以排除。

## 4. 技术分工（README 里要讲清楚）

- **seekdb = 课程知识库**：资料切块的存储、混合检索（向量 + IK 全文 + 课程/资料类型结构化过滤，一条 `DBMS_HYBRID_SEARCH`）、覆盖度打分，以及使用记录。
- **PowerContext = 学习者的记忆**：每个学习者 × 课程一个 Scope；掌握度卡片、错题、复习计划、会话小结；会话开始的 bootstrap 和按知识点的 prepare 召回。
- 两者都必须在主流程里真实起作用，不能只是"连上了"。

## 5. 约束

- **语言与框架**：Python 3.12 + FastAPI 后端；前端为后端直接托管的静态页面（HTML/CSS/原生 JS，不要构建步骤），图表用 ECharts（把 `echarts.min.js` 放进仓库，不依赖 CDN）。依赖用 `uv`（`pyproject.toml` + `uv.lock`）管理。
- **向量模型**：默认本地 `fastembed` + `BAAI/bge-small-zh-v1.5`（512 维），不需要任何付费 Key；Docker 镜像构建时预下载模型，运行时不联网。可选切换为 OpenAI 兼容的 embeddings 接口。
- **大模型**：可选，OpenAI 兼容的 chat completions（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`），不配置时全部功能走无模型路径。开发时本机有 Ollama（`http://127.0.0.1:11434/v1`，模型 `qwen3.5:9b`）可用来测试，但评审机器上没有，所以无模型路径必须完整。
- **部署**：`docker compose` 一键起三个服务：
  - `seekdb`：镜像 `oceanbase/seekdb:1.4.0-100000172026082615`，宿主机端口默认 10800；
  - `powercontext`：用 PyPI `powercontext[cli,server,seekdb]==1.4.1` 自建镜像，嵌入式 seekdb 存储，宿主机端口默认 18801；
  - `app`：ExamRadar，宿主机端口默认 18800。
  - 端口、密码都从 `.env` 读，仓库只提交 `.env.example`（占位值）。**仓库里不能出现真实密码或 API Key。**
  - 也要支持本地开发方式：容器只起 seekdb 和 PowerContext，应用用 `uv run` 在宿主机跑。
- **目录**：所有内容放在仓库的 `qoder/` 目录（就是你当前的工作目录）下。建议：`app/`（Python 包 `examradar` 和静态前端）、`samples/`（示例课程资料和验证样例，由产品负责人提供）、`scripts/`、`docs/`、`site/`（项目展示网站，后续单独开发）、`dev-records/`（开发记录，产品负责人维护，**不要修改**）。
- **工程质量**：代码结构清晰；关键逻辑（切块、覆盖度判定、间隔复习、PowerContext 客户端）有单元测试；有一个对真实 seekdb + PowerContext 跑的端到端验证脚本。
- 参考资料：`docs/reference/powercontext-1.4.1-notes.md`、`docs/reference/seekdb-1.4-notes.md`（产品负责人实测的接口细节和坑）。
